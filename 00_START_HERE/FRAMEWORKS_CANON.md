## 1. The four frameworks (the canon)

| Framework | What it is | Where it governs |
|---|---|---|
| **UDL 3.0 — CAST (2024)** | Universal Design for Learning Guidelines 3.0. Multiple means of engagement, representation, action & expression. Supports **add paths, never lower the goal.** | Every lesson, workbook, deck, and app screen. Access design + MTSS/WIDA supports. |
| **CER** | Claim · Evidence · Reasoning — the argument-writing spine (the ACADEMIC-reasoning performance task). | Student writing tasks; the canonical **workbook⇄app CER loop** (write on paper → self-grade on rubric → input to app → real-time feedback → revise). |
| **HIPPO** | Historical source analysis: **H**istorical context · **I**ntended audience · **P**oint of view · **P**urpose · **O**utside knowledge (the "Source It First" discipline; a.k.a. HIPP + Outside evidence). | Primary-source work, DBQ packets, deck "Source It First" bands. |
| **Future-Ready ("Ready Graduate")** | Portable readiness framework: four pillars on a shared 1–4 scale, per-unit leading indicators, a measurement engine, and behavioral proxies — a student's trajectory toward ACT / Ready Graduate benchmarks. | Every unit's rubrics, self-assessment, goal-monitoring, and durable-skill tracking. Full spec in §5. |

**Rule:** when a build references "the framework," name which one. UDL 3.0 is the access/design
spine; CER is the writing spine; HIPPO is the sourcing spine; Future-Ready is the trajectory spine.

## 2. The technology-value rule (LOCKED)

Refines the print-first product model (`PRODUCT_MODEL_DOCTRINE.md`) to a hard test:

> **All technology must exclusively bring value — and prove it with evidence.**
> **Print first. High-value technology only. Every function has a purpose; every purpose is high
> value; and it is used only if it cannot be done in print.**
> **We provide supports where supports are necessary or needed — never as decoration.**

Operationally, before any digital feature ships into the flow, it must answer all three:

1. **Can this be done in print?** If yes → it stays on paper. The app does not duplicate the page.
2. **Does it clear the Educational-Impact Gate?** (This is the real value proof.) Name the
   **high-impact instructional strategy** the feature delivers and its **research effect size** at or
   above Hattie's hinge point (**d ≈ 0.40**, preferably well above), **and** the reason print
   physically can't deliver that same benefit. Evidence base: **Hattie *Visible Learning*** ·
   **Rosenshine's Principles of Instruction** · **Marzano** high-yield strategies · **Black & Wiliam**
   (formative assessment) · **Roediger & Karpicke** (retrieval practice / spaced repetition). Examples:
   feedback (d ≈ 0.70), formative assessment, retrieval practice / spaced repetition, concept mapping /
   graphic organizers (Venn, d ≈ 0.60). "It feels engaging" is not evidence; an effect size + a
   print-can't-do-this reason is.
3. **Which framework does it serve?** UDL 3.0 access · CER/HIPPO performance · Future-Ready measure —
   or one of the five platform value pieces (analytics · real-time mastery · reteach · lesson-plan
   builder · gamification + read-aloud). No framework, no home → it's a paper question in disguise.

**SAMR + TPACK are descriptors, not the value bar.** SAMR (Substitution→Augmentation→Modification→
Redefinition) names the *kind* of integration and TPACK confirms tech/pedagogy/content fit — but a
"Redefinition" feature can still be low-impact, so neither proves value. Use them to describe the
move; use the Educational-Impact Gate (Q2) to prove it earns a screen.

Supports are provided **where necessary or needed** (UDL 3.0 + MTSS/WIDA) — they add paths for the
learners who need them and never lower the ceiling for anyone.

## 3. How the frameworks compose in a unit

- **UDL 3.0** shapes *how* every activity is presented and expressed (the access layer, on paper and
  on screen alike).
- **HIPPO** governs the source-analysis moments; **CER** governs the argument the student writes from
  those sources.
- **Future-Ready** measures the trajectory: the CER Closing Argument and the HIPPO source read are
  themselves the per-unit leading indicators scored on the shared 1–4 scale.
- The **workbook⇄app CER loop** is where three of the four meet: UDL-designed task, written as a CER,
  fed to the app for real-time feedback, logged as a Future-Ready leading indicator.

## 5. Future-Ready Framework — "The Flight Plan to a Ready Graduate" (full spec)

> _Staged verbatim from the owner. This is the source of truth for the Future-Ready framework and the
> body to lift into a skill (see §6). Portable skill set for embedding college-, career-, and
> life-readiness measurement into any K-12 lesson, unit, workbook, or assignment._

A student is climbing to a **30,000-foot goal**: the ACT college-readiness benchmarks and the state
**Ready Graduate** profile (a diploma + ACT composite ≥ 21, or the EPSO/credential equivalents).
Those are **lagging indicators** — measured once, too late to steer by. So we read the **instruments
every unit**: small, in-process **leading indicators** of the same skills, scored on one scale, so a
teacher can adjust *while there is still time*.

**How to use:** on any unit/lesson, (1) surface the standards, (2) run the per-unit measures below on
the shared 1–4 scale, (3) foreground ONE rotating pillar/skill as the unit's "Future-Ready" focus,
and (4) close with the measurement engine (Grade Check + Missing-work plan + Goal monitor). Rotate the
featured pillar across units so all four are hit.

### The one scale (use everywhere)
- **1 Emerging** — attempts it; missing key parts (needs supports).
- **2 Developing** — has the parts, not yet reliable (below trajectory — watch/support).
- **3 Proficient** — meets the standard independently. ✓ **on-trajectory (target).**
- **4 Advanced** — exceeds it; transfers the skill to new problems unprompted.
- **Rule:** flat or falling for two units → intervene.

### The four pillars (rotate the featured one each unit)

| Pillar | Measurable skills | Per-unit micro-measure (leading) | Year-end macro target (lagging) |
|---|---|---|---|
| **Academic Reasoning** (the ACT core) | Close reading · Argument writing (CER) · Mathematical modeling · Data analysis | CER Closing Argument 1–4 · source read (HIPP) · a data/math task | ACT benchmarks (Eng 18 · Math 22 · Read 22 · Sci 23) · Ready Graduate ≥ 21 |
| **College & Career Launch** | Communication (spoken) · Interview readiness · Financial literacy (FAFSA, money) · Planning & organization | Spoken "Mission Brief" rubric 1–4 · a career-skill task · materials-ready & on-time | FAFSA completion · early postsecondary (EPSOs) · industry credential · NACE career readiness |
| **Durable Character** (baseline hireability) | Grit · Work ethic · Integrity · Timeliness · Adaptability · Lifelong learning | Behavioral proxies (see below) | Durable-skills profile trend · employer "would-hire" · self-directed learner |
| **Civic & Collaborative** | Teamwork · Leadership · Civic responsibility | Peer/self teamwork rubric 1–4 · a logged leadership move · civic-action reflection | Ready Graduate civic disposition · NACE teamwork & leadership |

### The measurement engine (three instruments, every unit)
1. **Self-assessment — "Grade Check":** the student checks where they stand *before* checking their
   grade — logs into the gradebook (e.g., Skyward), records each class's current average and number
   of missing assignments, and self-scores the unit skill 1–4, then compares to the teacher's score
   (calibration is the signal — d ≈ 1.33 in Hattie).
2. **Rubric performance task:** a real product (e.g., a written Closing Argument or a spoken brief)
   scored on the 1–4 scale — a formative check that lets instruction adjust *before* the summative test.
3. **Goal monitor:** the student names a next-unit goal and checks whether they hit the last one
   (specific, challenging, monitored goals reliably raise performance — Locke & Latham).

### "Make the plan" — the follow-through step
- **Missing work · make the plan:** every missing assignment is points still earnable. List them, set
  a day to finish each, check it off.
- **Ask for help:** a self-advocacy email frame to schedule make-up work ("Dear ___, I am missing ___.
  Could I come in on ___ to make it up?") — asking professionally is itself a Ready-Graduate skill.

### Durable-skill behavioral proxies (make the "soft" skills visible)
Read as **indicators, not verdicts** — shaped by circumstances outside a student's control (home
responsibilities, jobs, device/internet access). Score on the same 1–4 scale from evidence you
already collect.

| Durable skill | Proxy you measure | Data source |
|---|---|---|
| **Timeliness** | % of work submitted on time (how often late) | assignment timestamps |
| **Work ethic** | task-completion % · attempts a revision when invited | completion & revision logs |
| Task persistence | finishes multi-step tasks; returns to the hard item | task progress · goal follow-through |
| Integrity | cites sources · submits own work | evidence use · academic-honesty checks |
| Self-assessment calibration | closeness of self-score to teacher score | self-vs-teacher gap |
| Responsiveness to feedback | score improves on the next attempt | attempt-to-attempt change |
| Communication | spoken-brief rubric (claim · evidence · delivery) | brief rubric 1–4 |
| Teamwork / Leadership | peer + self rating · logged leadership moves | rubrics · leadership log |
| Self-directed learning | sets & pursues self-chosen goals · logs curiosity questions | goal monitor · extension tasks |

### Guardrails
- Behavioral proxies describe **in-class behavior, not fixed traits**; they are conversation-starters,
  not labels. Never penalize circumstances outside a student's control.
- Leading indicators exist to **move** the lagging one — the point is time to adjust, not more grading.
  Prefer measures teachers already capture.
- "3 = on-trajectory" is the proposed bar; validate the ACT-projection cut-scores against your own
  cohort data before treating it as fixed.
- Confirm the official principle wording with the owner ("12 principles"); the four pillars above are
  the working sort of that list.

## 6. Promotion note — this is doctrine now, a skill next

The Future-Ready spec above is archived here as **doctrine on the work branch**, which is allowed.
It is **not yet a skill**, on purpose:

- `.claude/skills/` is **main-owned and read-only on work branches**; a new skill may only be added
  via a **dedicated skills-only PR to `main`** (enforced by `.claude/skills/lint_skills.py` +
  `skills-lint` CI). Adding it on a content branch would fail the build.
- **One job, one owner:** the registry (`.claude/skills/SKILLS.md`) currently assigns the
  *"future-ready principle"* to `history-hack-platinum-standard`. Promoting a standalone
  `future-ready-framework` skill requires reconciling that line — either the platinum-standard skill
  hands off the measurement machinery to the new owner and keeps only the principle, or the two are
  explicitly scoped so they don't collide. Resolve this **in the skills-only PR**, not here.

**When you're ready to promote:** open a skills-only PR to `main` that (a) creates
`.claude/skills/future-ready-framework/SKILL.md` from §5, (b) registers it in `SKILLS.md` with its
one job, and (c) edits the `history-hack-platinum-standard` ownership line to avoid the collision.
Until then, builders consume this framework from this doctrine file.
